\section{Safety and Security Requirements}
\subsection{Functional Requirements}
\begin{itemize}
    \item \textbf{SR-KT-1:} The KT shall enforce schema-level validation on all handoff submissions, rejecting any submission that leaves mandatory operational fields blank or below a minimum character threshold
    \item \textbf{SR-KT-2:} The KT shall verify that all cross-referenced bridge models, test result IDs, and rule versions stored in the Knowledge Repository exist and are valid before a handoff document is accepted.
    \item \textbf{SR-KT-3:} The KT shall track role succession states and block the archival of an outgoing lead's account until a designated successor or faculty advisor has been assigned to inherit the role records.
    \item \textbf{SR-KT-4:} The KT shall enforce a two stage publishing lifecycle. (Draft \(\rightarrow\) Review \(\rightarrow\) Publishing).
    \item \textbf{SR-KT-5:} The KT shall verify an acknowledgement is sent from the KR when publishing documents to show confirmation of documentation being saved.
    \item \textbf{SR-MT-1:} The MT shall automatically parse, validate, and convert all uploaded data into base standardized Units, rejecting datasets lacking unit metadata.
    \item \textbf{SR-MT-2:} The MT shall mandate the inclusion of grain orientation data on any wooden material test.
    \item \textbf{SR-MT-3:} The MT shall preform automated sanity checks to ensure all submitted data is within acceptable boundaries.
    \item \textbf{SR-SYS-1:} The project build system shall strictly enforce deterministic dependency resolution by pinning all direct and transitive third-party dependencies to immutable versions using lockfiles.
    \item \textbf{SR-SYS-2:} The deployment Pipeline shall enforce mandatory branch protection rules that block deployment to production environments; All automated unit tests execute and pass the CI/CD pipeline and any code changes must receive ibe documented.
    \item \textbf{SR-SYS-3:} The system shall provide fully containerized, reproducible deployment configurations (e.g., Dockerfile and docker-compose.yml) alongside automated setup scripts, standardized API documentation (e.g., OpenAPI/Swagger), and a maintainer onboarding guide that allows a new developer to build, deploy, and verify the full system locally within a single documented procedure.
\end{itemize}
