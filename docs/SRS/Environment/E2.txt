\nsection{E.2 Components}

The system will interact with the following external components:

\begin{itemize}

\item \textbf{Official Troitsky Organization - Concordia:} As the Troitsky club is generally officiated and organized fully by Concordia University's 
Troitsky organization, much of what is valued in the product depends on what is valued in the competition itself. Between years, rules are often revised, and different competition components are added, removed or modified. As is the case, the product will be heavily dependent on the organization 
and must allow for compliance and rule checking in line with the current competition standards.

\item \textbf{CAD Software Modelling Tools:} This is used by teams to create their STEP files, which will serve as the input for the Model Analysis.

\item \textbf{Static Model Analysis APIs:} For the modelling component of the product, external APIs will be used to perform the static analysis 
of the inputted STEP files. This will be used to calculate/create the output predictions and model data.

\item \textbf{Hosting and Data Storage Platform:} The product will require a platform or server to host the website and the shared database. This is where the 
repository of information, uploaded files and backups will be stored. 

\item \textbf{Materials Testing Department Setup:} As the product seeks to support the material testing department, the app will need to work around the data formats 
and the processing the team prefers.

\item \textbf{Club Sponsors and University Funding:} The MES and external sponsors dictate the funding that the club receives yearly. This funding may dictate the future upkeep of the 
product, being required for the hosting and data storage platform and potentially the external modelling API usage.

\end{itemize}
